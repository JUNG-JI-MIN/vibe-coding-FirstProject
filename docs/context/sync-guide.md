# 두 PC에서 작업 이어받기

## 처음 준비
- 두 PC에서 같은 Git 저장소를 사용한다. 이 설정 파일도 Commit/Push 또는 파일 복사로 전달해야 한다.
- `AGENTS.md`는 공통 규칙이며 `current.md`는 약 50줄의 현재 기준이다. 전체 기획서 재독부터 시작하지 않는다.
- 도구는 PowerShell 7에서 검증했다. Windows PowerShell 5.1 문법 검사도 통과했으며 Git이 필요하다.
- 스크립트 실행 정책 때문에 막히면 세션 정책 변경에 관한 현재 권한을 확인하거나 문서·Git을 직접 읽는다.

## 시작
1. 현재 PC의 `git status --short`로 미완료 변경을 확인하고 보존한다.
2. 번갈아 쓰는 공통 브랜치는 `git pull --ff-only`로 가져온다. 로컬 변경·분기·충돌이 있으면 먼저 해소한다.
3. 프로젝트 루트에서 `./tools/read-context.ps1`을 실행한다.
4. 현재 기준, 새 커밋/변경 파일, 새 인계, 관련 모듈을 확인한다. 첫 실행에는 초기 기준부터 확인한다.
5. 필요한 파일만 `git diff <기준SHA> HEAD -- <경로>`와 검색으로 자세히 읽는다.
6. 표시 제한으로 생략된 관련 항목은 추가 조회한다. `-MaxCommits`, `-MaxFiles`, `-MaxHandoffs`로 범위를 늘릴 수 있다.

## 확인 위치 저장
```powershell
$reviewedHead = git rev-parse HEAD
# 위 SHA까지의 변경을 확인한 뒤, 동일한 값을 전달한다.
./tools/read-context.ps1 -MarkReviewed -ExpectedHead $reviewedHead
```
- `$reviewedHead`는 검토를 시작할 때 확보한다. 검토 없이 종료 직전에 SHA만 얻어 저장하지 않는다.
- 이 명령은 `.local/codex-context.json`만 저장한다. 프로젝트 파일이나 Git 커밋을 바꾸지 않는다.
- 로컬 변경·미추적 파일·충돌이 있거나 예상 HEAD와 다르면 저장을 거부한다.
- 새 HEAD가 생기지 않았더라도 로컬 변경은 매 실행마다 다시 표시된다.
- 해당 PC에서 생성한 작업을 커밋한 후에도 확인한 HEAD로 저장할 수 있다.
- 최초 설정 파일들이 아직 커밋되지 않았다면 읽기는 가능하지만 커서 저장은 공유 커밋 생성 후에 한다.

## 종료와 전달
- 기능/설계 변경은 짧은 작업별 인계를 남긴다. `../handoffs/2026-10-14-context-bootstrap.md`를 형식 참고로 사용한다.
- 인계와 커밋 본문에 해당 작업의 요청 프롬프트를 짧게 요약한다. 커밋 본문은 `요청 프롬프트`, `변경 내용`, `검증`으로 구성한다.
- 확정 설계가 바뀌면 결정 기록과 현재 기준을 갱신하고, 파일 구조가 바뀌면 모듈 경로를 갱신한다.
- 확인한 코드·문서를 같은 커밋으로 공유한다. PC 간 전달은 Commit/Push 후 상대 PC에서 Pull이다.
- 동시에 작업하면 `codex/작업명` 브랜치를 사용한다. 공유된 결과를 합친 뒤 공통 기준으로 이어받는다.
- `.local/`, `.vs/`, 생성 빌드 출력, 로그인·개인 설정 전체를 공유 묶음에 넣지 않는다.
- 개인 Codex 설정 차이가 있다면 작업 규칙에 영향을 주는 항목만 따로 확인한다.

## 도구 동작
- 기본 실행은 로컬 상태를 읽기만 한다. Fetch/Pull/Push/병합/코드 변경은 하지 않는다.
- `-Base <SHA>`로 이번 조회의 기준을 지정할 수 있다. 저장된 커서는 바뀌지 않는다.
- 다른 컴퓨터·다른 체크아웃에서 복사한 커서, 삭제된 커밋, 조상이 아닌 커밋은 초기 모드로 돌아간다.
- 초기 모드는 현재 기준·모듈 안내·최근 인계부터 읽는다. 전체 과거 변경을 확인했다고 취급하지 않는다.
- 삭제·이름 변경은 Git 변경 목록으로 확인한다. 최신 인계의 현재 내용은 확인하되 과거 내용은 Git diff로 조회한다.
- 인계 본문은 파일당 최대 24줄, 기본 5개만 표시한다. 생략 시 추가 조회가 필요하다.
- 커서 저장은 사용자가 모든 내용을 읽었다는 자동 검증이 아닌, Codex의 명시적인 확인 선언이다.
