# 노트북 Codex에게 전달할 프롬프트

데스크톱에서 이 저장소에 두 PC 공통 작업 규칙과 변경분 인계 방식을 도입했다. 노트북에서도 아래 절차로 같은 기준을 사용해줘.

1. 먼저 현재 브랜치, 원격 주소, 로컬 수정·미추적 파일을 확인해. 노트북의 미완료 작업을 덮어쓰거나 버리지 마.
2. GitHub의 공유 커밋을 가져와. 번갈아 작업하는 공통 브랜치이고 로컬 변경이 없다면 `git pull --ff-only`를 사용해. 로컬 변경이나 분기가 있으면 먼저 작업을 보존하고 차이를 확인해. 충돌을 임의로 한쪽으로 덮어쓰지 마.
3. `AGENTS.md`와 `tools/read-context.ps1`이 있는지 확인해. 없다면 데스크톱 설정이 아직 전달되지 않은 것이므로 그렇게 알려줘. 기존 대화에서 규칙을 추측해 대체하지 마.
4. 루트 `AGENTS.md`를 읽고 `./tools/read-context.ps1`을 실행해. 최초에는 `docs/context/current.md`, `modules.json`, `decisions/001-shared-context.md`와 초기 인계를 읽어. 장문 기획서 전체를 먼저 읽지 마.
5. 검토할 전체 HEAD SHA를 확보해. 이후에는 이 PC의 마지막 확인 커밋 이후 변경 파일·새 인계·관련 설계 결정·해당 코드 차이만 우선 읽어. 로컬 수정도 별도로 확인하고, 출력에서 생략된 관련 항목은 추가 조회해.
6. 확장 기획 v0.3은 미확정 제안이고, 현재는 OpenGL 기반 플레이어 1명 + NPC 2명인 프로토타입이야. DirectX 이식은 후속 방향이므로 이번 동기화 작업에서 착수하지 마. 결정·구현·빌드·플레이 검증을 구분해.
7. 확인한 HEAD까지의 관련 변경을 모두 이해했고 로컬 변경이나 충돌이 없다면 `./tools/read-context.ps1 -MarkReviewed -ExpectedHead <검토한 전체 SHA>`로 노트북의 확인 위치를 저장해. 검토 후 HEAD가 바뀌면 추가 변경을 확인한 다음 다시 저장해. 데스크톱의 `.local/codex-context.json`을 복사하지 마.
8. 앞으로 동작·설계 변경 작업을 끝낼 때 작업별 짧은 인계를 `docs/handoffs/YYYY-MM-DD-작업명.md`에 남겨. 요청 프롬프트 요약, 변경, 이유, 관련 파일, 실제 검증, 미완료·다음 행동을 10~20줄로 적어. 확정 설계 변경은 작은 결정 파일과 current에, 파일 배치 변경은 modules에도 반영해.
9. 코드와 관련 설계·인계를 같은 커밋으로 공유해. 커밋 제목에는 핵심 변경을 적고 본문에는 `요청 프롬프트`, `변경 내용`, `검증`을 짧게 정리해. 대화 전체를 복사하지 마. Commit/Push는 현재 사용자 요청과 권한 범위를 따라 수행해. 두 PC가 동시에 작업하면 작업별 `codex/작업명` 브랜치를 사용해.

지금은 이 동기화 방식의 수신과 초기 확인까지 진행하고, 받은 커밋·노트북의 미완료 변경·확인 위치 저장 여부·남은 문제를 짧게 보고해줘. 상세 절차는 `docs/context/sync-guide.md`를 참고해.
