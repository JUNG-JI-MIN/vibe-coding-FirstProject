# 001: Git으로 공유하는 작은 설계 기준과 변경분 확인

- 날짜: 2026-10-14 (Asia/Seoul)
- 상태: 채택. 사용자가 두 PC의 공통 설계와 변경분 인계 방식 도입을 요청함.
- 문제: 대화·장문 기획서만으로 이어받으면 제안과 확정 요구사항, 구현과 검증이 섞인다.
- 결정: 규칙(AGENTS), 현재 상태(current), 모듈 경로(modules), 결정(decisions), 작업 인계(handoffs)를 구분한다.
- 전달: 코드와 관련 기록을 같은 Git 커밋으로 공유한다.
- 확인: 각 PC는 마지막 확인 커밋 이후의 파일·코드 차이와 새 인계만 우선 읽는다.
- 커서: PC·체크아웃별 로컬 JSON으로 유지하고 Git에서 제외한다. 읽기만으로 자동 갱신하지 않는다.
- 기록: 검토한 정확한 HEAD를 지정해야 갱신된다. 로컬 변경이 있거나 HEAD가 바뀌면 갱신을 거부한다.
- 한계: 커밋되지 않은 변경은 다른 PC에 전달되지 않는다. 인계 요약만으로 코드 검토를 대체하지 않는다.
- 한계: 다른 브랜치로 이동해 기준 커밋이 조상이 아니면 변경분 모드를 중단하고 현재 기준부터 확인한다.
- 출력: 표시 개수·줄 수를 제한하고 생략 사실을 알린다. 생략된 관련 변경은 추가 조회한다.
- 결과: 기존 장문 자료를 유지하면서 매 작업마다 읽는 양을 줄인다. 별도 검색 서버는 도입하지 않는다.
